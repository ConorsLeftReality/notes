URL (Uniform Resourse Locator)

Address/Location of a resource

Can be web link (DNS YAY) or local file address/path

Uniform Resourse Locator - Overall Layout

scheme://host:port/pathname?query#fragment

Most are optional, several have defaults (ports, scheme, etc)

URL - Scheme

Tells the browser what action to take when a user clicks on a link etc

E.G. HTTP, HTTPS, file, mailto

Other alternative are file (tells page to load file directly from local disk), but NEVER use it in a web page as the file could not exist and would throw an error.

mailto is ANOTHER scheme that is used to tell a website that a link is an email address. Will also be crawled and harvested by email harvesters (super sad not good)

chrome is another scheme, used to check data about chrome browser? (just not very useful in a website obviously)

- URL - Host

Which computer is the data stored on

Either an IP Addresses (IPv4, IPv6, whatnot) or a hostname

Personal Note: IPv6 is for pricks

IP Addresses are mapped to DNS records, and called to by their domain name

Hostname

- Hostname comprises of the name of a computer + domain name

E.G. www.cs.ucc.ie (www is name of server, cs.ucc.ie is domain name)

DNS (Domain Name System)

- Contains records matching a hostname to a static IP address (unless using DDNS)

- URL - Port

Servers can run many servers, but for these server to be running simultaneously, they need individual addressses with a common IP address

Solution: Port Number

Each software will have a specific Port Number

E.G.

  • Web Server - 80/443
  • Email Server (imap) - 143
  • Email Server (pop3) - 110
  • smtp - 25 (legacy), 587 (default), 456 (implicit TLS/SSl), 2525 (alt)
  • Proxmox - 8006
  • Grafana - 3000
  • ssh - 22

BUT this defaults to 80 because most web pages use 80 (or respond on 443 for HTTPS)

- URL - Pathname

Which file we want, and which folder (relative to the web server) it is in.

Unix File Systems

  • Folders - Directories
  • Root directory = /
  • Your users directory = ~/

Unix uses forward slashes, not back slashes like windows (ew)

File names - Avoid spaces and unnessecary punctuation, dont be a gimp, use underscores

Keep file names and directory names short BUT descriptive AND remember file extensions, and document if useful

Unix is case sensitive too, just name the file myfile.txt, not MYFILE.txt or MYFILE.TXT

Files have permissions too, and definitions for who can do what with files

  • Owner - Who owned/made the file/directory
  • Group - Users who belong to a group associated with the file/directory
  • Other - Anyone viewing the file/directory

There are definitons for permissions too

  • Read - view contents and list names of files in a directory
  • Write - Write/ modify files possible
  • Execute - Can run a file (if program/executable) and can traverse directory, and, if also have read perm, list the files, view contents and view perms

Filenames can be relative or absolute

Relative - example_directory/file_in_directory.txt

Absolute - /var/www/html/example_directory/file_in_directory.txt

You can also use ../ to go up a directory, E.G. im in a parallel directory and want to access another directory in the directory my working directory is located in

E.G. ../cats/siamese.html will exit current directory and access the cats directory within the overall directory that my working directory was also located within

Similar to Relative and Absolute paths, URLs have absolute and relative url types

Web Servers

  • nginx
  • Apache Web Server
  • Microsoft IIS (Internet Information Server)

For this module, we talk about apache web server

Apache is MODULAR, you can choose which modules you want for your use-case

These are enabled/disabled and configured through directives in the configuration file (E.G. httpd.conf)

Here is the simplest httpd.conf file possible

File Name: httpd.conf

ServerName www.example.com # Server's Name

Listen 80 # Port to listen to

DocumentRoot "/var/www/html" # Document Root being defined, web server's working directory

NOTE: The document root is the directory the web server uses that hosts all the web resources, basically web server's working directory

- The URL that someone enters to GET a webpage has a relative URL, but this is converted into an Absolute URL pathname by the web server, by concatonating the DocumentRoot and the GET requests URLs relative URL pathname

Absolute and Relative URLs:

External Link (on a different server)

  • Scheme + hostname/ip + absolute pathname

Internal Link (on same server/local server)

  • Scheme + hostname/ip + absolute pathname
  • Absolute Pathname
  • Relative Pathname

Apache Web Server - Additional Directives

-- 404 Errors --

You can define where to send people if the error is a 404 error, in the scenario that a webpage is missing

ErrorDocument 404 404.html

-- Index Files --

Suppose you search for a directory, how is it handled

Answer: DirectoryIndex index.html

Explanation: Apache will serve the file of said name in whatever folder you search up, (if the file exists, else 404)

Apache can also serve index pages in directories, which looks like this

<Directory />

*tab* Options +Indexes

</Directory>

*You can combine both of these directives if you want, or one or the other, or neither*
