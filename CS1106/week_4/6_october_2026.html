Recap

SQL Composite Functions

SQL can combine multiple conditions using the logical boolean operators AND, OR, and NOT

SELECT - Used to select columns from a table normally (SELECT * FROM table_name;)

Composite Functions covered were AND, OR, LIKE, NOT, ORDER BY

SQL - Useful code for LIKE

Say we want to find a field with the word 'or' in it, how do we do that?

SELECT * FROM table_name WHERE word LIKE '%or%'

The % means that in its place, can be 0 or more of any character

An underscore (_) can be used too, but this matches exactly one character

Here are examples

  • '%k' - Zero or more characters followed by k
  • 'ck%1' - 'ck' followed by zero or more characters followed by 1
  • '_a____%' - One character followed by 'a' followed by at least 4 characters

SQL - Concatenation

Say I had a variable, region, and I wanted to find countries with the region in its name

I would do this.

SELECT * FROM countries WHERE name LIKE '%' || region || '%';

The double lines (||) are used for concatenation, but are only one of many other ways to concatenate in SQL

Intro - Data and Arithmetic Operations

Data Analysis

Finding trends in data often requires processing the data before creating the result.

Data is usually stored at the lowest level of granularity possible (lowest level of detail).

NOTE: Null is used when it is necessary to record the absence of a value.

Attributes(?)

Each column in a database table will have a datatype/attribute.

E.G.

  • Name - TEXT
  • Region - TEXT
  • Area - in km**2 INT
  • Population - INT

Arithmetic Operations

Perform mathematical operations on table column(s) in a query

More completely, these can be performed on

  • A single column
  • Two or more columns
  • Constant values with column data
Operator Description
+ Addition
- Subtraction
/ Division
* Multiplication
% Modulus (remainder)

Example of possible use (Population Density)

example_arithmetic_operation.sql
SELECT name, population/area
FROM countries
WHERE region = 'Europe'
ORDER BY population/area DESC;

Aggregation

Summarise the data from all or part of a table

Aggregation Function

A function that performs a calculation on a set of values and returns a single value

SQL Aggregation Functions

COUNT() is the number of values of an attribute

E.G. Counts the number of rows in a specified field

SELECT COUNT(name) FROM countries; returns the number of values in the name column of table countries

SELECT COUNT(gdp) FROM countries; return the number of values in the gdp column of table countries

Query 1 could return a higher value than Query 2, as some of the fields in the gdp column could be NULL

Other Aggregation Functions

  • MIN () - Smallest Value in column
  • MAX () - Highest Value in column
  • SUM () - Sum of a numerical column
  • AVG () - Average value of a numerical column
Note

If the list of attributes in SELECT is a single aggregation function, the result is a 1 x 1 table

Unique Values

DISTINCT ensures each value in a column is only counted once, which can be used with any aggregate function but makes most sense with COUNT ()

E.G. SELECT COUNT(DISTINCT region) FROM countries; would return the number of unique regions in a table

Grouping

Aggregate functions are applied to groups of rows

If no group is specified, there is a single, implicit group consisting of all the rows in the table

By defining a group, aggregate functions can calculate totals, counts, the average, smallest, and largest values within each group

How do we group?

Add the clause GROUP BY to the SELECT statement

E.G. 
SELECT region, SUM(population) 
FROM countries
GROUP BY region;

This returns the sum of the population for each region, based off of common regions for each country

HAVING

WHERE picks which rows go into the groups. HAVING adds conditions on the result of the GROUP BY (so it can use aggregates). It doesn't change which rows are used to calculate the aggregates, only which groups appear in the result.

having.sql
SELECT region, COUNT(*), AVG(gdp), SUM(area)
FROM countries
GROUP BY region
HAVING SUM(population) > 1000000000;

Clause Order Gotchas

SQL clauses are applied in a fixed order (FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT), so:

  • No aggregates in WHERE - WHERE population = MAX(population) is an error ("misuse of aggregate function"), because aggregates haven't been calculated yet when WHERE runs
  • No HAVING without GROUP BY on non-aggregated columns - gives "HAVING clause on a non-aggregate query"

LIMIT and OFFSET

LIMIT n returns at most n rows (useful for "top 3", pagination, or just transferring less data). OFFSET k skips the first k rows first. Only makes sense if the result is in a known order (ORDER BY). Not every database supports LIMIT the same way.

limit_offset.sql
-- Page 2 of the smallest countries, 10 per page
SELECT name, area
FROM countries
ORDER BY area
LIMIT 10 OFFSET 10;
