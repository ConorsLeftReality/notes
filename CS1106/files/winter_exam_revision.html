Exam Format

1.5 hours, 70 marks, answer ALL questions. No calculators. It's been the exact same 3 questions for the last 3 years:

  • Q1 (10 marks) - draw an ER diagram from a written scenario
  • Q2 (18 marks) - one table: CREATE TABLE, INSERT, UPDATE, DELETE and simple SELECTs
  • Q3 (42 marks) - 6 queries (7 marks each) over a 3-4 table schema. This is 60% of the paper

Past scenarios:

  • 2023: travellers/trips/locations (ER), restaurant reviews (Q2), hotel bookings (Q3)
  • 2024: university modules/lecturers/students (ER), Christmas presents (Q2), movies/actors/castings (Q3)
  • 2025: TV series/episodes/characters/actors (ER), Gruff Tours trips (Q2), world cities/countries/languages (Q3)

Q1 - ER Diagrams

Read the scenario and pick out the nouns (entities) and the verbs between them (relationships)

  • Every entity gets its attributes and a key (underline it)
  • Label every relationship with its cardinality: 1:1, 1:N or M:N
  • Watch for attributes that belong to a relationship, not an entity, e.g. a traveller's score for a location (2023), the character an actor plays in a series (2025)
  • Watch for "but not the same ones every semester" type wording - that usually means the relationship needs a date/semester on it

See Lecture 11 - Designing Databases and Lecture 12 - Normalisation

Best practice for Q1: Lecture 14 - ER Modelling Example works through a whole scenario (the COMPANY database) the same way the exam does: nouns to entities, verbs to relationships, then cardinalities. Lecture 13 - Normalisation Example shows splitting one messy table into proper tables, which also helps with the 2025-style design question in Q2

Q2 - One Table (DDL and DML)

Easy marks, 3 each. Know the syntax off by heart. See Lecture 6

q2_patterns.sql
CREATE TABLE trips (
    id INTEGER PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    dep_date DATE,
    length INTEGER,
    places INTEGER,
    price DECIMAL(7,2)
);

INSERT INTO trips VALUES
    (1, 'Treasures of Sicily', '2026-07-04', 7, 30, 1299.99),
    (2, 'Rome in a Weekend', '2026-09-12', 3, 20, 549.00),
    (3, 'Lakes of Kerry', '2027-01-01', 5, 25, 799.50);

UPDATE trips
SET price = price * 2
WHERE dep_date BETWEEN '2026-07-01' AND '2026-07-31';

DELETE FROM trips
WHERE dep_date < '2024-01-01';

SELECT *
FROM presents
WHERE occasion = 'birthday'
ORDER BY price_limit DESC;

Increase by 5% = SET rating = rating * 1.05. Dates are always 'YYYY-MM-DD' in quotes.

2025 had a design part (8 marks)

"Add customers who book trips". A customer can book many trips and a trip has many customers, so it's M:N: make a customers(id, name, address) table and a link table bookings(customer_id, trip_id) with both as the key, and each one a foreign key to its table.

Q3 - Queries (the big one)

The same handful of patterns come up every year. If you can do these, you can do Q3:

  • Join + filter + ORDER BY (often 2 sort keys, one DESC). Use DISTINCT if they say "each hotel should appear at most once". See Lecture 7 and Lecture 8
  • GROUP BY + HAVING - "for each city/year... only those with at least 1000". See Lecture 5
  • Biggest/smallest - sometimes "do not use MAX", so use >= ALL or ORDER BY + LIMIT 1
  • Pairs - self join the table to itself, with a.id < b.id so each pair only shows once
  • "Did NOT..." - NOT IN (subquery). See Lecture 10
  • Compare to an aggregate - per capita GNP bigger than the English-speaking average: subquery that works out the average
  • Dates - a month is a BETWEEN, and two bookings overlap if each one starts before the other ends
q3_patterns.sql
-- Largest city WITHOUT using MAX (2025)
SELECT name
FROM cities
WHERE population >= ALL (SELECT population FROM cities);

-- Pairs of cities with the same name in different countries (2025)
SELECT c1.name, c1.country_code, c2.country_code
FROM cities AS c1 JOIN cities AS c2
    ON c1.name = c2.name AND c1.country_code < c2.country_code;

-- Films from 1961 NOT starring Gregory Peck (2024)
SELECT title, score
FROM movies
WHERE yr = 1961
AND id NOT IN (SELECT c.movieid
               FROM castings AS c JOIN actors AS a ON c.actorid = a.id
               WHERE a.name = 'Gregory Peck');

-- "Good" years: 10 or more films scoring 7.5+ (2024)
SELECT yr, COUNT(*)
FROM movies
WHERE yr BETWEEN 1960 AND 2000 AND score >= 7.5
GROUP BY yr
HAVING COUNT(*) >= 10;

-- Overlapping bookings for the same guest in the same hotel (2023)
SELECT h.hotel_name, g.guest_name, b1.arr_date, b1.dep_date, b2.arr_date, b2.dep_date
FROM bookings AS b1
    JOIN bookings AS b2 ON b1.hotel_num = b2.hotel_num
                       AND b1.guest_num = b2.guest_num
                       AND b1.booking_num < b2.booking_num
    JOIN hotels AS h ON b1.hotel_num = h.hotel_num
    JOIN guests AS g ON b1.guest_num = g.guest_num
WHERE b1.arr_date < b2.dep_date AND b2.arr_date < b1.dep_date;
Tip

7 marks each, so even a half-right query gets marks. Write the FROM/JOIN part first, then WHERE, then GROUP BY/ORDER BY.
