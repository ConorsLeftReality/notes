Normal Forms Recap

The design principle: one fact in one place, avoid redundancy as much as possible

  • 1NF - every value is atomic (can't be split) and no repeating groups. Each row is uniquely identifiable - "the key"
  • 2NF - in 1NF, and no partial dependencies: non-key columns depend on the whole primary key - "the whole key"
  • 3NF - in 2NF, and no transitive dependencies: non-key columns depend only on the key, not on other non-key columns - "and nothing but the key"

There's also BCNF (Boyce-Codd), a stricter version of 3NF that some textbooks use

Functional Dependency

Y is functionally dependent on X (X → Y) if whenever two rows agree on X, they're guaranteed to agree on Y too

Worked Example - Movies

Start with a spreadsheet of movies: title, year, genre, director, director's country, and an Actors column with a comma-separated list of names

Unnormalised (UNF)

  • Multiple actors in one cell (or Actor, Actor, Actor columns = repeating groups)
  • No primary key - two movies could share a title
  • Redundant data - Denis Villeneuve and Canada appear over and over

UNF → 1NF

Split the actors so each row has one actor (one row per movie-actor pair). Same data, more rows

Give each movie a MovieID and each actor an ActorID, then the key is the composite (MovieID, ActorID)

1NF → 2NF

Look at the dependencies:

  • MovieID → Title, Year, Genre, Director, Director Country
  • ActorID → Actor

These only depend on part of the key, so split them out. Now 3 tables:

  • Movies(MovieID, Title, Year, Genre, Director, Director Country)
  • Actors(ActorID, Actor)
  • Castings(MovieID, ActorID) - the identifying relationship

2NF → 3NF

In Movies: MovieID → Director → Director Country. Country depends on the director, not the movie, so that's a transitive dependency

Give directors a DirectorID and move them into their own table. Now 4 tables:

  • Movies(MovieID, Title, Year, Genre, DirectorID)
  • Directors(DirectorID, Director, Director Country)
  • Actors(ActorID, Actor)
  • Castings(MovieID, ActorID)
Exercise

Write the SQL DDL (CREATE TABLE) for these 4 tables. What constraints would you add? (primary keys, foreign keys, NOT NULL...)
