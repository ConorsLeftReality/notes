What is a URL?

A URL, or Uniform Resourse Locator, is used as the address/location of a resource. A URL is often used by a web browser and in websites.

A URL can be a web link or a local file path/address.

Layout of a URL

scheme://host:port/pathname?query#fragment

Most of these parts are optional, and many have defaults (see other sections)

Summary
  • A URL is a Uniform Resourse Locator
  • A URL is the address/location of a resourse
  • A URL can either be a web link or a local filepath

URL - Scheme

A URL Scheme tells the browser what action to take when a user clicks on a hyperlink.

Examples of Schemes

  • HTTP - Hypertext Transfer Protocol (what web servers and clients use)
  • HTTPS - HyperText Transfer Protocol Secure (same as HTTP, but encrypted end-to-end)
  • file - tells page to load file directly from local disk, but bad to use as files have possibility to be missing
  • mailto - used to tell a website that a hyperlink is an email address, but will be harvested by email harvesters (not good)

Schemes such as chrome also exist, but not much use to us (different browsers for users, and not of much use in general)

URL - Host

The Host section of a URL tells us which computer data is stored on. The Host can be in the form of either an IP Address or a hostname (below).

Hostnames

A Hostname comprises of the name of a computer and the domain name

E.G. www.cs.ucc.ie (www is the name of the server, cs.ucc.ie is the domain name)

DNS (Domain Name System)

IP Addresses are in the form of numbers (255.255.255.255 is the form for IPv4, and 0000:0000:0000:0000:0000:0000:0000:0000 for IPv6)

In order to simplify this for users, we use DNS servers that relate an IP address of a server to a domain name (E.G. google.com is linked to an IP like 102.123.132.231)

DNS is covered in future years in networking, dont worry about it past this information

URL - Port

Servers can run many servers, but for these server to be running simultaneously, they need individual addressses with a common IP address

SOLUTION: Network Ports

It would be very inefficcient if we could only have one piece of software running on a computer, so each piece of software on a computer (that needs network access outside of its own computer) can get a port to access a network from.

Imaginary Computer 01

These are the network-interacting programs running on out imaginary computer

  • Web Server - 80/443
  • Email Server (imap) - 143
  • Email Server (pop3) - 110
  • smtp - 25 (legacy)
  • Proxmox - 8006
  • Grafana - 3000
  • ssh - 22

See how our imaginary computer is running 7 different programs? This is possible due to each program having its own port!

BUT this defaults to 80 if left empty because most web pages use 80 (or respond on 443 for HTTPS)

URL - Pathname

The pathname is used to say which file we want, and which folder it is in.

Unix File Systems - A foundation we need to continue

For Web Development 1, we use Unix Based Operating Systems (Ubuntu Linux), so we must know how files are laid out

Basic terms for Unix Filesystems

  • Folders == Directories
  • Root Directory == /

Unix uses forward slashes (/), not back slashes like Windows file systems(\)

Basic Advice for using Unix Filesystems

  • Avoid spaces and unnessecary punctuation in filenames (Use underscores instead of spaces, NEVER USE SPACES IN FILENAMES ITS A PAIN TO WORK WITH)
  • Unix is case sensitive too, so keep everything lowercase (unless told not to, some stuff will want specific casing)

File Permissions

Files have permissions too, and definitions for who can do what with files

  • Owner - Who owned/made the file/directory
  • Group - Users who belong to a group associated with the file/directory
  • Other - Anyone viewing the file/directory

These are some permissions that are used in Unix systems

  • Read - View contents and list names of files in a directory
  • Write - Write / modify files possible
  • Execute - Can run a file (if program/executable) and can traverse directory, and, if also have read perm, list the files, view contents and view permissions

Relative and Absolute filenames

Filenames can be in 2 forms

  • Relative - example_directory/file_in_directory.txt
  • Absolute - /var/www/html/example_directory/file_in_directory.txt

A Relative filename assumes we are looking for a file from a specific starting point (the folder we are in currently), but an absolute filename assumes we start at the very start of the directories, in the Root Directory (/)

Tip

In relative pathnames, you can also use ../ to go up a directory.


                       / (Root Dir.)
                  __________|______________
                  |                 |                       |
                dogs           cats                     birds
                  |                 |                       |
            pug.html       siamese.html          budgie.html

For example, imagine we are in pug.html (so our directory is dogs), to go from where we are to siamese.html, we do ../cats/siamese.html. So we ../ to go up a layer (to the root directory co-incidentally), then from there we go to the cats directory, and then open the siamese.html webpage

Web Servers

Web servers are the software that server computers use to serve webpages to people (clients)

  • Apache Web Server
  • Microsoft IIS (Internet Information Server)
  • nginx

In CS1115, we only care about Apache

Apache Web Server

Apache is a free and open-source web server software that was the most popular web server for decades. Apache is MODULAR, so you can choose which modules you want for your webserver, depending on what you want it to do. These are enabled/disabled and configured through directives in the configuration file (E.G. httpd.conf)

Here is the simplest httpd.conf file possible

httpd.conf

ServerName www.example.com # Server's Name

Listen 80 # Port to listen to

DocumentRoot "/var/www/html" # Document Root being defined, web server's working directory
Note

There are 2 things to note

  • The document root is the directory the web server uses that hosts all the web resources, basically web server's working directory
  • The URL that someone enters to GET a webpage has a relative URL, but this is converted into an Absolute URL pathname by the web server by concatonating the DocumentRoot pathname and the GET requests URL's relative pathname

Absolute and Relative URLs

External Link (on a different server)

  • Scheme + hostname/ip + absolute pathname

Internal Link (on same server/local server)

  • Scheme + hostname/ip + absolute pathname
  • Absolute Pathname
  • Relative Pathname

Apache Web Server - Additional Directives

404 Errors

You can define which page to call to when there is a 404 error with code like ErrorDocument 404 404.html

Index Files

Suppose you search for a directory, how is it handled

ANSWER: DirectoryIndex index.html

EXPLANATION: Apache will serve the file of said name in whatever folder you search up, (if the file exists, else 404)

Apache can also serve index pages (that show the contents of a directory as a basic HTML file menu) with code like this

httpd.conf

<Directory />

    Options +Indexes

</Directory>
Note

It is possible to have multiple directives, or some, or none. As long as the basics (stated above) are present in httpd.conf, all is OK
