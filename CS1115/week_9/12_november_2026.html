Responsive Web Design - What is it?

Responsive Web Design is used to adapt the layout of a website to the characteristics of the window/device

Responsive Components

Some of the things we have seen so far are already helpful for RWD.

  • Liquid layouts, using relative units or percentages.
  • Flexbox, assuming, e.g. we allow items to wrap and to flex.
  • Grid layout, if we use, e.g., repeat(auto-fill, 20em)

When these do not suffice, then use media queries.

CSS Media Queries

RWD uses media queries to adapt to a range of devices.

media_queries.css
body {
    color: white;
    background-color: black;
}

@media screen and (min-width: 600px) {
    body {
        background-color: red;
    }
}

@media screen and (min-width: 800px) {
    body {
        background-color: blue;
    }
}

@media screen and (min-width: 1000px) {
    body {
        background-color: yellow;
    }
}
  • Use a black background.
  • But, if the viewport is at least 600px, use a red background.
  • But, if the viewport is at least 800px, use a blue background.
  • But, if the viewport is at least 1000px, use a yellow background.

If the viewport is 1200px, all of these are true, but the background ends up yellow because of the cascade (ordering: the later rule wins).

Anatomy of a Media Query

A simple media query @media screen and (min-width: 800px) { … } is made of:

  • the media type, e.g. screen (another one is print, and there are 8 more)
  • an expression with a media feature (e.g. min-width) and a value (e.g. 800px) in brackets
  • some CSS between curly braces, which the browser only applies if the query is true
Container Queries

Media queries style things based on the device (e.g. viewport width). CSS now also has container queries, e.g. @container (width > 800px) { … }, which style things based on the size of an element's container. Not covered in the lectures.

Media Queries for RWD

RWD uses media queries to adapt to a range of devices, e.g. a single-column layout for narrow viewports but multi-column layouts for wider ones. You can also adapt individual components, e.g. stacked vs horizontal nav menus, or a logo above vs beside a slogan.

(Remember: sometimes you don't need media queries at all - flexboxes can adapt on their own.)

When making websites, it is best to code for mobile devices first

  1. Write your core CSS:
    • colours; borders; fonts; margins; padding
  2. Write CSS for the narrowest reasonable viewport widths:
    • e.g. a single-column layout
    • (maybe you won't need any CSS!)
  3. Write successive media queries that apply extra styles for relevant breakpoints:
    • e.g. multi-column when viewport min-width allows it;
    • e.g. even ultimately a fixed-width design for very wide viewports.

Simple RWD example

A simple example of RWD would be...

  • Narrow-Screen Devices: use a one column layout for the webpage
  • Wide-Screen Devices: use a two column layout for the webpage
simple_rwd.css
/* Core CSS goes here (colours; borders; fonts; margins; padding) */

/* Single-column layout for narrow devices */
body {
    margin: 0;
}

/* Two-column layout for wider devices */
@media screen and (min-width: 600px) {
    body {
        width: 80%;
        margin: 0 auto;
        display: grid;
        grid-template-columns: 1fr 3fr;
        grid-template-areas: "top top"
                             "middle-left middle-right"
                             "bottom bottom";
    }
    header { grid-area: top; }
    nav    { grid-area: middle-left; }
    main   { grid-area: middle-right; }
    footer { grid-area: bottom; }
}

Common Screen Size Breakpoints

Breakpoint Typical devices
320px For small screen devices, like phones, held in portrait mode
480px For small screen devices, like phones, held in landscape mode
600px Smaller tablets held in portrait mode
768px Ten-inch tablets held in portrait mode
1024px Ten-inch tablets held in landscape mode, as well as some laptop, netbook and desktop displays
1200px For widescreen displays, primarily laptop and desktop browsers

Problem: there are far more devices than this table assumes, and it isn't future-proof. Instead, let the content decide the breakpoints: start with the small screen, widen it until it looks bad, and add a breakpoint there. A breakpoint is any point where you need a media query to make the page (or one component) look right.

Some people use em instead of px in media queries, so breakpoints scale when the user zooms, and so you can base them on readability (people are most comfortable with lines of 45-75 characters).

One problem with Media Queries

On many small-screen devices, there is a difference between the layout viewport and the visual viewport. E.g. an iPhone's layout viewport is 980px wide but its visual viewport is only 320px. The page is drawn on the layout viewport, then shrunk down to fit the visual one.

Media queries use the layout viewport, and so might not work.

Thankfully, there is a fix

To make RWD work on these devices, we need to make the two viewports of equal size. Add the following inside the head element of each page of HTML:

head.html
<meta name="viewport" 
      content="initial-scale=1.0, width=device-width" />

(This isn't standard HTML, and putting visual settings in HTML isn't ideal, but the CSS alternative, @viewport, isn't widely supported.)

Images in Responsive Layouts

The problem with images

In liquid layouts, you don't know how much space is available for your images.

If the image is wider than the available space, it will overflow its container.

E.G. an aside that's 25% of the window is 300px wide in a 1200px window, but only 250px in a 1000px window - so a 275px image fits in the first but not the second.

One option is to hide the overflow with CSS, e.g. figure { overflow: hidden; } (overflow can be visible (default), hidden, scroll or auto). Usually, though, we let the browser scale the image:

Images for Liquid Layouts

Responsive Web Design recommends we set the max-width to 100% in the CSS:

img_max_width.css
img {
    max-width: 100%;
}

If the image is narrower than its container, it will display at its normal size. If it is wider than its container, it will be scaled down to match the width of the container.

Alternatively, you could set the width to 100%:

img_width.css
img {
    width: 100%;
}

Then the image scales up or down to match the container.

  • Downside: the browser spends time scaling, and you might download a big image just to shrink it (wasting bandwidth)
  • Keep height: auto so the aspect ratio is preserved (or if you set the height, leave the width as auto)
  • For known shapes, the CSS aspect-ratio property helps, e.g. .thumb { aspect-ratio: 1/1; }, .hero { aspect-ratio: 16/9; }

More problems that exist... :(

  • Resolution switching problem: you want to serve smaller image files to narrow screen devices, and also optionally you want to serve different resolution images to high density/low density screens
  • Art direction problem: you want to serve different images for different layouts — for example a wide image showing a full scene for a desktop layout, and a narrower, cropped image showing a close-up for a mobile layout

Resolution Switching

HTML solves this using the srcset and sizes attributes, e.g.:

html_res_switch_1.html
<img
     srcset="wombat-small.jpg 480w,
             wombat-large.jpg 800w"
     sizes="(max-width: 600px) 480px,
            800px"
     src="wombat-large.jpg"
     alt="..." />
html_res_switch_2.html
<img 
     srcset="wombat.jpg,
             wombat-hi-res.jpg 1.5x"
     src="wombat-hi-res.jpg"
     alt="..." />
  • You prepare several versions of the image (different sizes or resolutions)
  • In the first example, srcset lists each file and its width (using w, not px). sizes hints to the browser: if up to 600px of viewport is available, use the 480px image, otherwise the 800px one
  • The second example picks by screen resolution (the 1.5x image for high-density screens)
NOTE

Do note, even though we are using modern HTML such as 'srcset' and 'sizes', still include a 'src' attribute in case the browser does not understand the modern HTML (or none of the hints apply).

The Art Direction Problem

Here you don't just want a smaller copy of the same image, you want a different image for different layouts, e.g. the full wide scene on desktop, but a cropped close-up on mobile.

HTML solves this using the picture and source elements, e.g.

html_art_direction.html
<picture>
    <source media="(max-width: 799px)" srcset="wombat-cropped.jpg" />
    <source media="(min-width: 800px)" srcset="wombat.jpg" />
    <img src="wombat.jpg" alt="..." />
</picture>
