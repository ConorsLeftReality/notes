Introduction to relationships - Lecture 1

Modelling relations between objects

Computer science is all about models - Representing them, using them, and understanding their properties

The basics of set representation allows us to talk about collections, and about which objects are in which collection

But we need more than this for modelling - we need to represent the connections between different objects, or the relationships between objects, and these relationships will have to be more general than functions

Overview of Computer Science

How does a computer work ==> How are computers networked together ==> How do we write software to run on computers ==> How do we represent information ==> What applications are possible ==> How do users interact with computers?

Networking

Some processes maintained by the OS allow communication with other devices on a network

Devices communicate using various protocols - agreed schemes for sending and receiving messages

Devices on a network are arranged in different patterns, or topology

Network Topologies

Networking cont.

Networks can be connected together, making a network of networks. This is called a WAN (wide area network) for internet networking. The internet and World Wide Web are examples of a WAN

Relational Databases

The standard representation of data in databases is based on entities and the relationships between them

Relational databases often rely on multiple relations (e.g. find all students that have Prof. Kenny as their teacher has 2 relations)

Representing Relations

You can represent relations using...

  • a matrix
  • a table
  • an arrow diagram
  • a set of ordered pairs
NOTE

Every relations has...

  • a source (what are we relating from)
  • a target (what are we relating to)
  • an order (what order is the relation e.g. a student can be a student of a teacher, but a teacher cant be a student of a student)
  • an inverse relation

Formal Definitions (the 3 slides below, written out)

  • Let A and B be sets. R is a binary relation between A and B if and only if R ⊆ A × B - i.e. a relation is just a set of ordered pairs (a,b)
  • A is the source and B is the target: source(R) = A, target(R) = B
  • a is R-related to b if and only if (a,b) ∈ R. We write it as R(a,b), aRb, or just (a,b) ∈ R (like how we write 3 < 7 instead of (3,7) ∈ <)
  • If a is not related to b: (a,b) ∉ R, or ¬R(a,b)

A function is a special type of relation. If f : A → B, then f = {(a,b) | a ∈ A, b ∈ B, b = f(a)}, so f ⊆ A × B. The difference:

⊆ A × B⊆ A × B

Functional or Non-Functional Relationships

A binary relation R ⊆ A x B is functional if for each a ∈ A, there is exactly one b ∈ B, s.t. (a,b) ∈ R

Properties Of Relations - Lecture 2

This lecture covers

  • Operations on relations
  • Relations over multiple sets
NOTE

In this subject, we call relations by letters, like sets. Look at example below to understand more.

Operations on relations

Standard set operations on relations produce new relations

Let R ⊆ A x B and S ⊆ CxD be two relations.

Then R⋃S, R⋂S, R \ S (difference), RxS and R' are all relations

Relations are ordered

R(a,b) does not mean R(b,a), even if A and B are the same set. E.G. "<" over {0,1,2,3,4} contains (0,1) but not (1,0).

Inverse of a relation

The inverse R-1 is all the original pairs flipped: (y,x) ∈ R-1 if and only if (x,y) ∈ R. E.G. the inverse of "is the mentor of" is "is mentored by".

Composing 2 relations together

If R ⊆ A × B and S ⊆ B × C, then "S after R" (written S ∘ R) is a new relation from A to C: (a,c) ∈ S ∘ R if and only if there's some b with (a,b) ∈ R and (b,c) ∈ S. You follow an arrow in R, then an arrow in S.

Two simple standard relations

A null relation between two sets is the empty set (i.e. nothing in first is related to anything in second)

(to get useful information out of this, we still need to know the source and target)

A universal relation between two sets is just the cartesian product of the sets (i.e. everything in first is related to everything in second)

n-ary relations

Let A1, A2, ..., An be sets.

R is a relation over A1, A2, ..., An if and only if R ⊆ A1 x A2 x ... x An

Any element of R is an n-tuple (a1,a2, ..., an), with each ai ∈ Ai

E.G. a database table is an n-ary relation: the STUDENT table (Name, Id, Address, Degree, MId) is a relation over 5 sets, and each row is a 5-tuple.

Selection and Projection

  • Selection - keep only the tuples of R that satisfy some condition C (a new relation, a subset of R). E.G. select films with year > 1970. Like SQL's WHERE
  • Projection - keep only some of the attributes of each tuple, throwing the rest away. E.G. project the film table over (title, genre). Like choosing columns in SQL's SELECT
