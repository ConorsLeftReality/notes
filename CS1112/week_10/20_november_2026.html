Logical Arguments

How do we check an implementation meets its specification? Truth tables get huge very quickly, and logical equivalences are too limited. So we argue it, formally, sticking to the rules of logic

  • An argument is a sequence of statements leading from some initial facts (premises) to a conclusion
  • It's valid if whenever the premises are true, the conclusion has to be true too
  • The rules only depend on the form of the statements, so this is called formal reasoning

E.G. 1) if your swipe card is accepted, you can enter E4, 2) your swipe card is accepted, so 3) you can enter E4

With p = "swipe card accepted" and q = "can enter E4": p → q, p, therefore q. The truth table shows the only row where p and p → q are both T also has q = T, so it's valid

Written as: p → q, p ⊢ q

Valid does NOT mean true

"If Enda Kenny is from Mars, he has two heads. He's from Mars. So he has two heads." The form is correct (valid), but the facts are false, so the conclusion isn't true

Rules of Inference

A rule of inference lets us add a new statement to our collection. If a statement matches the pattern exactly (e.g. → at the top of the syntax tree for modus ponens), we can use it. X and Y can be whole complex statements

Any logical equivalence also gives a rule, but that's too restrictive

  • Modus Ponens: x → y, x ∴ y
  • Modus Tollens: x → y, ¬y ∴ ¬x
  • Unit Resolution: x ∨ y, ¬x ∴ y
  • Simplification: x ∧ y ∴ x
  • Addition: x ∴ x ∨ y
  • Conjunction: x, y ∴ x ∧ y
  • Chaining: x → y, y → w ∴ x → w
  • Elimination: x ↔ y, x ∴ y
  • Resolution: x ∨ y, ¬y ∨ w ∴ x ∨ w

Building an Argument

If one rule isn't enough, chain them. Each rule adds a new fact you can use for the next one. As long as you only use valid rules and equivalences, the argument is valid

Number every new line, and say which lines it came from, which rule, and what you substituted for x and y

Example

Premises: 1. p → q, 2. ¬q ∧ r, 3. ¬p → s, 4. s → t. Show t

  1. ¬q - from 2, Simplification [x=¬q, y=r]
  2. ¬p - from 1 and 5, Modus Tollens [x=p, y=q]
  3. s - from 3 and 6, Modus Ponens [x=¬p, y=s]
  4. t - from 4 and 7, Modus Ponens [x=s, y=t]

Password Example

p = correct password, o = open area access, r = restricted area access, s = can read sensitive data

Premises: 1. ¬p → o, 2. s → r, 3. ¬(o ∧ r), 4. ¬p. Show ¬s

The slides leave this for us. One way to do it:

  1. o - from 1 and 4, Modus Ponens
  2. ¬o ∨ ¬r - from 3, De Morgan
  3. ¬r - from 6 and 5, Unit Resolution [x=¬o, y=¬r]
  4. ¬s - from 2 and 7, Modus Tollens

Soundness and Completeness

  • Sound - anything you can derive with the rules really is true whenever the premises are
  • Complete - anything that's true whenever the premises are can be derived with the rules

We don't prove this in CS1112
