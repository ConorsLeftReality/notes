Virtual Memory

In early computers, memory was small and expensive. In those days, programmers had to spend a lot of time making programs small enough to fit on the small amount of memory they had

The traditional solution was to use a secondary memory, such as disk, to hold parts of the program, called overlays, and to move these overlays from secondary memory to main memory such as RAM.

Definition

Virtual memory is a memory management technique that uses space on a storage drive (like an SSD or HDD) to extend physical RAM

The idea was to separate the concepts of address space and memory locations and to break the code up into pieces, called pages.

Paging

The technique for automatic overlaying is called paging, and the group of program instructions are called pages

Addresses referred to by programs and the compiler are collectively called the virtual address space, and the physical memory locations, the physical address space.

A memory map or page table specifies for each virtual address what the corresponding physical address is.

Paging gives the programmer the illusion of a large, continuous, linear main memory, the same size as the virtual address space.

Whenever an address is referenced, the proper instruction or data word appears to be immediately available.

Because the programmer can program without reference to the paging mechanism, it is said to be transparent.

Note

In virtual memory, a disk is required to hold the whole program and all its data

When changes are made to the copy in main memory, they should be reflected on the disk (eventually).

Question. Do we really have to replace the contents of the whole physical memory every time a new page is referenced?

We can get around this by making smaller pages and by partitioning the physical address into logical pieces also. These pieces are called Page Frames and are chosen to be the same size as the (smaller) pages.

Page sizes are usually between 512 Bytes and 64 KBytes (sometimes up to 4 MBytes), and are always a power of 2

Implementing Paging

With 32 bits we can make 232 (about 4 billion) addresses. With 4KB pages, that's about 1 million pages

The page table has one entry for every page in the virtual address space

E.G. 64KB of virtual memory = 16 pages of 4KB. If we only have 32KB of main memory, that's 8 page frames of 4KB

  • The whole physical memory can be addressed with 15 bits (215 = 32K)
  • Each instruction inside a frame can be addressed with 12 bits (212 = 4K)

Page Faults and Demand Paging

When a program refers to an address on a page that isn't in main memory, a page fault happens

The OS then has to:

  1. Read the page in from the disk
  2. Put its new physical location in the page table
  3. Repeat the instruction that caused the fault

This is called demand paging - a page is only brought in when it's asked for, not in advance

Working Set Model

Programs don't use their address space evenly, their references cluster on a small number of pages (the locality principle)

The working set is the set of pages used by the most recent memory references. It changes slowly, so when a program restarts we can guess which pages it'll need and load them in advance

Page Replacement

To make room for a new page, another page usually has to go back to the disk. The OS tries to pick the page that's least useful

  • LRU (Least Recently Used) - evicts the page used least recently, since it probably isn't in the working set any more
  • FIFO (First In First Out) - evicts the oldest page, no matter when it was last used. Each frame has a counter that goes up after every page fault, and the page with the highest counter goes
Thrashing

If the working set is bigger than the number of page frames, no algorithm works well (LRU is the least bad). A program that causes page faults constantly is said to be thrashing

If a page being evicted hasn't been changed since it was read in (likely if it's program code, not data), it doesn't need to be written back to disk. If it has been changed, the disk copy is out of date and it must be written back first
