ASCII Tables

  • ASCII is a standardised table where each number in a byte (0-255) is associated with a symbol or an action
  • ASCII Tables in machines can vary depending on locale
  • ASCII Table values can be represented in Hexadecimal too, often displayed on same table?
  • ASCII Table is an effective way to associate a character with a number.
  • Difference between character '5' and number 5? look up and update info here
  • There is also a difference in upper and lowercase characters, make sure to remember this

An ASCII Table has a Bit Pattern, Decimal, Signed Decimal, Hexadecimal value and a character

NOTE

A signed decimal is the same as decimal until it passes Decimal=127 (midway point to 256 values), and then goes from -128 to 0 for the second half of the 256 ASCII Table values.

At the machine level, the question always is "how many bits do we have and how are those bits interpreted"

  1. Character variables are only 1-byte in size, Integer values are normally many bytes in size
  2. Strongly typed programming languages are strict in distinguishing between characters and integers and will not allow the progammer to combine them in expressions

Interpreting groups of bits

We recognise that we only have a fixed number of bites to represent items of information on our computer.

Representation of data comes from a particular combination of bits

Representation of a combination of Bits requires context!!!

  • If interpreting as natural numbers, each combination will interpreted as a binary number of 2**n - 1, where n is the number of bits
  • If interpreting as instructions, each part of the combination will be interpreted as different parts of an instruction
  • If interpreting as colours, parts of the combination will be assigned as a value for Red, Green and Blue

Representing Negative Numbers

How do we represent negative numbers?

Since, for a given number of bits, we are limited to 2**n combinations

If we wish to represent both positive and negative numbers, we must evenly share these combinations between positive and negative numbers

  • 2**n is always even
  • Therefore we could say that range 0 => (2**n-1) - 1 is positive, and the range (2**n-1) => (2**n) - 1 is negative
  • This would evenly split the range for both positive and negative numbers

NOTE: The Most Significant Bit for positive numbers is 0, and the MSB for negative numbers is 1. Easy way to differenciate between pos and neg numbers

If we add a positive and negative binary number, the addition and subtraction works out the exact same as with decimal numbers

The unbalanced (Due to requiring a value for 0) convention for representing both positive and negative numbers is called "Two's Compliment"

The convention of representing negative numbers works for any amount of bits, such as 32 bits
