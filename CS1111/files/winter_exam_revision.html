Exam Format

1.5 hours, 80 marks, attempt ALL questions (2 questions, 40 marks each). Non-programmable calculators allowed (2025).

  • Q1 - lots of short theory parts (a) to (h), 2-12 marks each
  • Q2 - virtual memory / cloud, then Samphire programs worth 26-30 marks
Free marks

The exact same number, 7FAC13B4, was asked for big/little endian in both 2023 and 2025. The cloud IaaS/PaaS/SaaS stack question was word-for-word the same too.

Theory That Keeps Coming Up

Abstraction levels (6-12 marks, both years)

From top to bottom: Problem-oriented language → Assembly language → Operating system machine → Instruction Set Architecture (ISA) → Microarchitecture → Digital logic. 2-3 sentences each.

Endianness (4-6 marks, both years)

7FAC13B4 = bytes 7F AC 13 B4, at addresses n to n+3:

  • Big Endian: 7F, AC, 13, B4 (most significant byte at the lowest address)
  • Little Endian: B4, 13, AC, 7F (least significant byte at the lowest address)

Memory (see Lecture 8 and Lecture 9)

  • DRAM vs SRAM - DRAM is a capacitor, needs refreshing, cheap and dense (main memory). SRAM is flip-flops, no refresh, fast and expensive (cache)
  • Parity - one extra bit per byte to make the count of 1s even (or odd). Detects 1-bit errors, can't fix them. ECC uses several extra bits to detect multi-bit errors and correct single-bit ones
  • Locality of reference - temporal (same data again soon) and spatial (nearby data soon). Cache keeps recently used data and whole blocks around it in fast memory
  • Word alignment - the speed vs space trade-off: aligned words are faster to fetch but waste memory as padding

Instructions (see Lecture 10 and Lecture 11)

  • Immediate addressing - operand is in the instruction: MOV AL,15. Register addressing - operand is in a register: ADD AL,BL
  • Same mnemonic, different op-codes: MOV AL,15, MOV AL,[15] and MOV [AL],BL are all "MOV" but need different op-codes because the operand types differ
  • Instruction fields: op-code, operands/addresses, addressing mode. More op-code bits = more instructions, more address bits = more memory reachable, but a longer instruction word

Virtual Memory and Cloud

See Lecture 19 and Lecture 20

MMU translating 32-bit virtual to 15-bit physical (12 marks, 2023)

With 4KB pages, the offset is 12 bits. So the 32-bit virtual address = 20-bit page number + 12-bit offset. The page table maps the page number to a 3-bit page frame number (8 frames). Physical address = 3-bit frame + same 12-bit offset = 15 bits. If the page's present bit is 0, that's a page fault.

Page replacement (4 marks, 2025)

LRU - evict the page used least recently. FIFO - evict the oldest page.

The cloud stack (6 marks, both years)

Stack: 1 Applications, 2 Data, 3 Runtime, 4 Middleware, 5 O/S, 6 Virtualization, 7 Servers, 8 Storage, 9 Networking

  • IaaS: you manage 1-5
  • PaaS: you manage 1-2
  • SaaS: you manage none of them

Also know 2 of the cloud characteristics, e.g. on-demand self-service and rapid elasticity.

Samphire Programs

26-30 marks every year. Past questions:

  • 2025: a delay subroutine using AL, called with a 2-digit number from the keyboard (20 marks), and "compile" an if/else into Samphire (10 marks)
  • 2023: add 10 numbers stored from address 80 using ORG and DB, and show the result on the VDU (16 marks). Read 10 characters and write them to the VDU in reverse using the stack (10 marks)
delay_subroutine.asm
start:
  in 00          ; tens digit
  sub al, 30     ; ASCII to number
  mul al, 0a
  push al
  pop bl         ; bl = tens * 10
  in 00          ; units digit
  sub al, 30
  add al, bl     ; al = the 2-digit number
  call 70        ; delay for al counts
  jmp start

org 70           ; delay subroutine
delay:
  dec al
  jnz delay      ; keep counting down until al = 0
  ret

end
reverse_with_stack.asm
  mov cl, 0a     ; 10 characters
read:
  in 00
  push al        ; stack is last in, first out...
  dec cl
  jnz read
  mov bl, c0     ; start of the VDU
  mov cl, 0a
write:
  pop al         ; ...so they come back out reversed
  mov [bl], al
  inc bl
  dec cl
  jnz write
end
sum_ten_numbers.asm
  mov bl, 80     ; address of the first number
  mov al, 0      ; running total
  mov cl, 0a     ; 10 numbers
loop:
  mov dl, [bl]   ; arithmetic can't read memory directly, so copy it first
  add al, dl
  inc bl
  dec cl
  jnz loop
  ; then split al into tens and units with DIV/MOD 0a,
  ; add 30 to each and MOV them to [c0] and [c1] (like lab 3)
  end

org 80
db 1
db 2
db 3
db 4
db 5
db 6
db 7
db 8
db 9
db 0a
If/else into Samphire

Read A and B into registers, CMP them, then a conditional jump (JS if A < B) to the else part, with a JMP at the end of the if part to skip over the else. See Lecture 14 and Lecture 17.
