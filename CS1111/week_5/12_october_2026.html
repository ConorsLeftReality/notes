Accessing Memory

RECAP FROM LAST DAY

A memory address is a binary number

A 16-bit word consists of a high byte and a low byte (first 8 bits == high byte, last 8 bits == low byte)

To fetch a 16 bit word, we need to read first byte and then second byte after it to get 16 bits

A way to make this more efficient is by making a 2 byte read default for a 16 bit program, or a 4 byte read for 32 bit programs etc.

Words and word length

In modern computers, bytes are normally grouped into 4 or 8-byte words and instructions manipulate an entire word as a single entity.

The number of bits is the word length

The word length reflects the structure and operations of a computer.

  • Register sizes (32 or 64 bit?)
  • Maximum data transfer between processor and memory in a single operation
  • Data bus size
  • Largest possible physical address size

Word Alignment

To simplify design and speed up execution, many architectures require words to be aligned in memory at addresses that are multiples of the word size.

This is called aligning on natural boundaries

In order to accommodate for this, words are placed at addresses in the interval of the words length in bytes

E.G. 4 byte words will be in addresses 4,8,12,16 ... etc

Similarly, 8 byte words will be in addresses 8,16,24,32 ... etc

One option, to use the memory more fully is to use multiple word lengths for each kind of data or to adopt the length of the smallest data type and to encode other data types as multiples of this minimum size (usually 1 byte)

Both schemes can adversely affect performance by either complicating memory address calculations to account for non-alignment or by increasing the number of memory accesses when fetching data greater than 1 byte in size.

Thus, the tradeoff is ultimately speed vs storage

Error Checking - Parity

Modern memory is reliable, and controllers usually only check for errors at start-up. But some memory chips that need extra reliability use parity checks: one extra bit for every 8 bits of data.

  • Even parity: when writing, count the 1s in the byte. If odd, set the parity bit to 1; if even, set it to 0. So the total number of 1s (including the parity bit) is always even
  • Odd parity: the opposite - the total is always odd

When reading, the chip checks the byte still follows the scheme. If not, it reports an error.

E.G. (even parity): 11011011 has six 1s, so parity bit = 0. 11010011 has five 1s, so parity bit = 1. (With odd parity it'd be 1 and 0.)

Limitations

  • Parity can detect an error but can't tell you which bit is wrong, so it can't fix it
  • If two bits flip in the same byte, the parity still looks fine and the error goes unnoticed (unlikely, but possible)
  • Parity can be done per word instead of per byte, and is used in lots of communication schemes too

Error Correcting Codes (ECCs), used in mission-critical systems, use several extra bits so they can detect multi-bit errors and correct single-bit errors.

Endianness

Endianness is the order the bytes of a word are stored in memory. For a 4-byte word with bytes 1 (most significant) to 4:

  • Big Endian: the most significant byte (Byte 1) goes at the lowest address, then Byte 2 at the next address, etc.
  • Little Endian: the most significant byte goes at the highest address, Byte 2 at the next lower address, etc.

Locality of Reference

Items "close to each other" tend to be accessed many times in a short period. Two kinds:

  • Temporal locality (in time): the same data is used again soon, so keep it in fast storage
  • Spatial locality (in space): nearby addresses are used soon, so keep nearby data in fast storage too

Locality comes from program structure (loops, ifs, data structures), which makes memory access predictable. Caching and prefetching exploit this - it's why the memory hierarchy works.
