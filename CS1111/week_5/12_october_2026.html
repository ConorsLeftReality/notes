Accessing Memory

RECAP FROM LAST DAY

A memory address is a binary number

A 16-bit word consists of a high byte and a low byte (first 8 bits == high byte, last 8 bits == low byte)

To fetch a 16 bit word, we need to read first byte and then second byte after it to get 16 bits

A way to make this more efficient is by making a 2 byte read default for a 16 bit program, or a 4 byte read for 32 bit programs etc.

Words and word length

In modern computers, words are normally grouped into 4 or 8-byte words and instructions manipulate an entire word as as single entity.

The number of bits is the word length

The word length reflects the structure and operations of a computer.

  • Register sizes (32 or 64 bit?)
  • Maximum data transfer between processor and memory in a single operation
  • Data bus size
  • Largest possible physical address size

Word Alignment

To simplify design and speed up execution, many architectures require words to be aligned in memory at addresses that are multiples of the word size.

This is called aligning on natural boundaries

In order to accomocate for this, words are placed at addresses in the interval of the words length in bytes

E.G. 4 byte words will be in addresses 4,8,12,16 ... etc

Similarly, 8 byte words will be in addresses 8,16,24,32 ... etc

One option, to use the memory more fully is to use multiple word lengths for each kind of data or to adopt the length of the smallest data type and to encode other data types as multiples of this mininum size (usually 1 byte)

Both schemes can adversely affect performance by either complicating memory address calculations to account for non-alignment or by increasing the number of memory accesses when fetching data great than 1 byte in size.

Thus, the tradeoff is ultimately speed vs storage
