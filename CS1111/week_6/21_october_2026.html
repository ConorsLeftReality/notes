Samphire Registers

General Purpose Registers

The CPU has four general-purpose registers called AL, BL, CL and DL. These are eight bits or one byte wide. Registers can hold unsigned numbers in the range 0 to +255 and signed numbers in the range −128 to +127. These are used as temporary storage locations. Registers are used in preference to RAM locations because it takes a relatively long time to transfer data between RAM and the CPU. Faster computers generally have more CPU registers or memory on the CPU chip.

The registers are named AL, BL, CL and DL because the 16-bit version of this CPU has more registers called AH, BH, CH and DH. The ‘L’ means Low and the ‘H’ means High. These are the low and high ends of the 16-bit register.

Special Purpose Registers

The special purpose registers in the CPU are called IP, SR and SP.

IP is the Instruction pointer

This register contains the address of the instruction being executed. When execution is complete, IP is increased to point to the next instruction. Jump instructions alter the value of IP so the program flow jumps to a new position. CALL and INT also change the value stored in IP. In the RAM displays, the instruction pointer is highlighted red with yellow text.

SR is the Status Register

This register contains flags that report the CPU status.

  • The ‘Z’ zero flag is set to one if a calculation gave a zero result.
  • The ‘S’ sign flag is set to one if a calculation gave a negative result.
  • The ‘O’ overflow flag is set if a result was too big to fit in a register.
  • The ‘I’ interrupt is set if interrupts are enabled. See CLI and STI.

SP is the Stack Pointer

The stack is an area of memory organised using the LIFO last in first out rule. The stack pointer points to the next free stack location. The simulator stack starts at address BF just below the RAM used for the video display. The stack grows towards address zero. Data is pushed onto the stack to save it for later use. Data is popped off the stack when needed. The stack pointer SP keeps track of where to push or pop data items. In the RAM displays, the stack pointer is highlighted blue with yellow text.

Random Access Memory

The simulator has 256 bytes of ram. The addresses are from 0 to 255 in decimal numbers or from [00] to [FF] in hexadecimal. RAM addresses are usually given in square brackets such as [7C] where 7C is a hexadecimal number. Read [7C] as “the data stored at location 7C”.

How To: Writing Samphire Programs

Step-by-step recipes for the instructions from this lecture, based on the lecture's example programs (moves, increment/decrement, arithmetic/logic) and the labs.

How to write and run a program

  1. Type your program into the Samphire editor, one instruction per line
  2. Use ; for comments - everything after it on the line is ignored
  3. All numbers are hexadecimal: 10 means sixteen, 0A means ten
  4. Finish the program with end
  5. Assemble it, then step through one instruction at a time to watch the registers and RAM change, or run it continuously

How to move data (mov)

The destination always comes first: mov destination, source. All of these use the same mnemonic, but they're different machine instructions with different opcodes:

InstructionTypeOpcodeWhat it does
mov al, 40immediateD0put the value 40 into al
mov bl, [03]direct (read)D1copy the value at address 03 into bl
mov [80], aldirect (write)D2copy al into address 80
mov cl, [al]register indirect (read)D3copy the value at the address held in al into cl
mov [dl], blregister indirect (write)D4copy bl into the address held in dl
NOT ALLOWED in Samphire
  • mov al, bl - no register-to-register moves (use push bl then pop al instead)
  • mov [cl], 80 - you can't put a number straight into memory. Put it in a register first, then move the register into memory

How to add or take away 1 (inc / dec)

increment_decrement.asm
mov al, 10
inc al      ; al = 11
inc al      ; al = 12
dec al      ; al = 11
dec al      ; al = 10
end

inc al does the same as add al, 01 but takes less memory, and usually has its own hardware support, so it skips the ALU. (An example of Amdahl's law: make the common case fast.)

How to do arithmetic and logic

  1. Put the first value in a register: mov al, 10
  2. Apply the operation with the register first: add al, 05 (immediate, opcode B0) or add al, bl (register, opcode A0)
  3. The answer replaces the first operand, so the old value of al is lost. If you need it later, copy it somewhere first

Available: add, sub, mul, div, mod (remainder), and the bitwise and, or, xor, not.

arithmetic_logic.asm
; Calculate 10*4+3 (all hex)
mov al, 10
mul al, 04   ; al = 40
add al, 03   ; al = 43

; Logic works bit by bit
mov cl, 03   ; 0000 0011
mov dl, F0   ; 1111 0000
or  cl, dl   ; cl = F3 (1111 0011)
not cl       ; cl = 0C (0000 1100)
end

How to write a character to the screen (VDU)

  1. The screen is RAM addresses C0 to FF. Whatever ASCII code you put there gets displayed
  2. Keep the next screen address in a register: mov al, C0
  3. Put the character's ASCII code in another register: mov bl, 48 ('H')
  4. Write it with a register indirect move: mov [al], bl
  5. Move to the next position with inc al, and repeat

This is how Lab 2 prints "Hello" (48, 65, 6C, 6C, 6F).
