The Assembly Language Level

"High-Level" programs are translated to assembly language programs

There are two distinct steps

  1. Generation of an equivalent program
  2. Execution of the newly generated program
Note

There is a one-to-one correspondance of assembly language statements to machine instructions

The function of Assembly language is to abstract away from the machine language by using symbolic names for instructions instead of binary or hex values

- E.G. ADD, SUM, MUL and DIV

Symbolic names can also be used for memory locations

- E.G. The assembler generates values for symbolic names that are used to indentify memory locations

- Everything that can be done in machine language can be done in assembly language.

In contrast, many instructions, registers and low-level features are not directly available to high level language programmers.

Note:

Notes

1. Languages for system programming, such as C, have the syntax of a high-level language but also low-level access to the machine.

2. An assembly program can only run on one family of machines, but high-level languages can run on many families of machines

Why program in Assembly?

Performance

An expert assembly language programmer can produce code that is much smaller and much faster than a high-level language programmer

For some applications, speed and size are critical.

E.G. Embedded systems and performance-critical real-time applications (flight systems etc.)

Access to the machine

Some procedures need complete access to the hardware, something usually impossible to high-level programmers

E.G. the low-level interrupt and trap handlers in an operating system and the device controllers in many embedded real-time systems fall into this category

The Samphire simulator

Features of Samphire

  • 8-bit CPU
  • 256 Bytes RAM
  • Input and Output ports
  • Simulated peripherals
  • Editor and Assembler
  • Single step through programs
  • Continuously run programs

Samphire Peripherals

  • Keyboard input
  • Memory Mapped VDU
  • Traffic Lights
  • Sevel Segment Display

Samphire Architecture

`

Samphire Registers and RAM

  • All registers are 8-bits wide
  • 4 General Purpose Registers: al, bl, cl, dl
  • Special Purpose Registers
    • Instruction Pointer (IP)
    • Status Register (SR)
    • Stack Pointer (SP)
  • 256 Bytes RAM, Addresses [0] to [FF]
